# AI_NOTES — как использовался ИИ

Весь код пишет Claude Code (веб, облачная машина). Пользователь ставит задачу, проверяет результат и принимает решения. Здесь записаны только реальные случаи из этой работы.

### Этап 1 — План
- Задача: структура файлов, схема таблицы, формат ответов API, список тестов. Без кода.
- Что сделал ИИ: предложил план: одна таблица `trips` (колонка `end_at`, потому что `end` — ключевое слово SQL), время хранится строкой в `+05:00`, колонка `day` с индексом, POST в виде «INSERT → при IntegrityError сравнить».
- Ошибка / что упало: ошибок нет. В плане было два упущения, их нашёл пользователь (ниже).
- Решения пользователя:
  - ветки: каждый этап отдельным PR из рабочей ветки сессии (`claude/loving-maxwell-x3vjvs`), PR называется «Stage N — <название>», мерж через merge commit;
  - первый коммит в `main` — `CLAUDE.md` и `.gitignore`;
  - время нормализовать до секунд (`isoformat(timespec="seconds")`) при хранении и при сравнении на дубль, иначе лексическая сортировка ломается на микросекундах. В плане ИИ этого не учёл;
  - `strict` только на int-полях через `Field(strict=True)`, не на всю модель, чтобы datetime парсился из строки. ИИ предложил просто «флаг strict», без уточнения, а strict на всю модель запретил бы ISO-строки для datetime;
  - комиссия в seed: `amount * 15 // 100`, без float и round;
  - в клиенте показывать человеку `detail[].msg` из ответа 422;
  - по возможности добавить тест на гонку (два потока, один id).

### Этап 2 — Backend + seed + тесты
- Задача: FastAPI + sqlite3, seed из `data/trips.json`, тесты сводки и API.
- Что сделал ИИ: `summary.py` (чистые `trip_day` и `build_summary`), `models.py` (валидация, нормализация времени в `+05:00` с отбрасыванием долей секунды), `db.py` (идемпотентный `create_trip`), `seed.py`, `main.py`. Сгенерировал `data/trips.json` скриптом: 35 поездок за 4 дня, поездка через полночь `t18`, поездка в `Z` — `t26`. 48 тестов.
- Ошибка / что упало:
  - `git push` из облачной машины вернул 403 («Claude doesn't have GitHub access to phoboslove/testmapptaxi»). Через GitHub API запись тоже не прошла: `403 Resource not accessible by integration`. Пользователь выдал Claude GitHub App доступ к репозиторию, после этого пуш прошёл.
  - pytest выдал предупреждение `StarletteDeprecationWarning: Using httpx with starlette.testclient is deprecated; install httpx2 instead`. В плане ИИ стоял `httpx`, рассчитанный на более старую версию Starlette.
- Как исправили и кто нашёл: предупреждение заметил ИИ в выводе pytest. В `requirements.txt` `httpx` заменён на `httpx2==2.13.1`, предупреждение пропало. Проверено в чистом venv: `pip install -r requirements.txt` → 48 passed.
- Тест на гонку: два потока с `threading.Barrier` одновременно шлют один POST через `TestClient`, ожидается ровно один 201, один 200 и одна новая запись. 30 прогонов подряд — все зелёные. Честное ограничение: тест проверяет результат, но не гарантирует, что оба `INSERT` действительно пересеклись по времени. Корректность при любом порядке обеспечивает `PRIMARY KEY` в SQLite, а не тест.
- Решения пользователя: правки к плану из этапа 1 применены. Время хранится и сравнивается с точностью до секунд, поэтому `08:10:00.250` и `08:10:00` считаются одной поездкой: это 200, а не 409.

### Этап 3 — Ручная проверка API
- Задача: запустить сервер, прогнать curl: days, trips, summary, POST 201 → 200 → 409 → 422 по каждому правилу, поездку через полночь. Добавить curl в README.
- Что сделал ИИ: запустил uvicorn на чистой БД и прогнал скриптом 25 запросов. Все коды ответов совпали с правилами: 201 / 200 / 200 для того же момента в `Z` / 409, после этого за день одна поездка. `t18` есть в 02.10 и нет в 03.10, `t26` (`19:30Z`) попала в 04.10 как `00:30+05:00`.
- Ошибка / что упало: тесты этого не ловили, но curl показал проблему в формате ответа. Проверки «end > start» и «commission ≤ amount» были в `model_validator`, поэтому в 422 стояло `loc: ["body"]` без имени поля, а в тексте был префикс `Value error, `. По такому ответу клиент не сможет показать ошибку под нужным полем. Это недочёт ИИ из этапа 2.
- Как исправили и кто нашёл: нашёл ИИ при ручной проверке. Проверки перенесены в `field_validator` полей `end` и `commission`, ошибки бросаются через `PydanticCustomError` без префикса. Теперь `loc: ["body","end"]`, `msg: "end must be later than start"`. Добавлен тест на `loc` и `msg` для обеих проверок, итого 49 passed.

### Этап 4 — Flutter-клиент
- Задача: один экран (переключатель дня, сводка, список поездок), добавление поездки в bottom sheet, состояния «загрузка / пусто / ошибка», `flutter analyze` и `flutter test`.
- Что сделал ИИ:
  - поставил Flutter 3.47.7 (stable) в облачную машину: архив 1,5 ГБ скачался без проблем;
  - создал проект (web + android) и написал `lib/api`, `lib/utils/format.dart`, виджеты, экран;
  - id поездки — uuid, создаётся один раз при открытии формы;
  - ошибки 422 разбираются по `detail[].loc/msg` и показываются под нужным полем, 409 и ошибки сети — внизу формы;
  - время на клиенте тоже считается от фиксированного UTC+05:00, а не от часового пояса устройства;
  - 15 тестов: форматирование денег и длительности, время Алматы, разбор ответов 201/200/409/422 и ошибки сети через `MockClient`.
- Проверка в браузере: ИИ собрал web-версию, запустил backend на чистой БД и прошёл сценарии в headless Chromium (Playwright):
  - экран дня, суммы сверены с данными;
  - поездка через полночь с пометкой «→ 00:15 след. дня»;
  - список дней по тапу на дату;
  - форма, клиентская валидация (POST не уходит);
  - экран «Нет связи» → «Повторить»;
  - тёмная тема и широкий экран;
  - **повтор после потерянного ответа**: Playwright пропустил первый POST до сервера (201), но оборвал ответ клиенту. Повторное «Сохранить» ушло с тем же uuid и получило 200 «Такая поездка уже есть». В базе одна поездка.
- Ошибка / что упало:
  - Chromium в облаке не смог скачать CanvasKit с `www.gstatic.com`: `ERR_TUNNEL_CONNECTION_FAILED`, сетевая политика окружения отвечает 403 на этот хост. Проверочную сборку собрали с `flutter build web --no-web-resources-cdn` (CanvasKit внутри сборки). На обычный запуск `flutter run -d chrome` у пользователя это не влияет.
  - Недочёт UI, нашёл ИИ на скриншоте: на экране ошибки до первой успешной загрузки FAB «+» выглядел активным, но ничего не делал. Теперь FAB скрыт, пока день не загружен.
  - Ошибка в тестовом скрипте, не в приложении: первый клик по «Повторить» попал мимо кнопки (неверная координата). После исправления координаты «Повторить» отработал.
  - Ошибка ИИ в скрипте остановки сервера: `kill` по `ps | grep "uvicorn app.main"` убил собственный shell, потому что в его командной строке тоже была эта подстрока. Перешёл на PID-файл.
  - Android-сборку в облаке не запускали (нет Android SDK). Манифест дополнен разрешением `INTERNET` и `usesCleartextTraffic` для HTTP к локальному серверу.
